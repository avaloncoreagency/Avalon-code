# Architecture
core.ts contains typed read-only REST adapters, bounded retries/pagination, source facts, correlation, reconciliation and resume generation. runtime.ts gates server caching behind owner authorization. Next routes validate UUID membership through existing Supabase SSR helpers.
CLI snapshots use atomic rename and a synchronization lock. GitHub Actions serializes runs and can preserve AES-256-GCM encrypted snapshots as artifacts. Unavailable providers retain last-known data marked STALE; absent data is UNKNOWN. Freshness limit two hours, scheduled cadence hourly (best effort), dashboard cache five minutes.
Incremental Issue reads overlap cursors by one minute; IDs deduplicate events and older Issue updates are ignored. Full reconciliation: bridge:sync -- --full. Events bounded to 2000; API pages bounded to 30 with explicit incomplete failure.
Runtime caches are per-instance and disappear on restart. No always-on server, database table, webhook endpoint or paid orchestrator is introduced. GitHub push events plus scheduled/manual Actions provide the hybrid trigger.
