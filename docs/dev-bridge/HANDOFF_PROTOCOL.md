# Symmetric handoff
Create a canonical Issue with exactly one owner:miguel or owner:samuel and one module label. Record priority, acceptance criteria, branch, SHA, PR, dependencies, blockers, verification date and a literal line `Next action: concrete command or action`. Link from the PR using Refs #N (or Closes/Fixes #N).
Run bridge:sync, then bridge:handoff -- --issue N --as samuel --state Ready (or --as miguel in reverse). Ready requires passing CI. Use --publish to record an idempotent envelope in the Issue; private packages remain local/encrypted. An actor's declaration is REPORTED, not verified identity acceptance.
States: Draft, Ready, Accepted, In progress, Completed, Superseded, Blocked. Accepted needs explicit --accept; completed work must have canonical acceptance evidence and is not inferred from package generation. No handoff can prove someone else accepted it.
The other owner runs bridge:resume -- --issue N --as OWNER. Fresh GitHub and exact current SHA are mandatory. Review warnings, use a separate git worktree with commands in the package, run relevant tests, commit referencing the Issue, and submit a PR. Never overwrite an active branch.
If source SHA changed, regenerate explicitly with --regenerate after review. If GitHub is unavailable, inspect cached state but do not resume until verified. Validate packages using bridge:check. CLI --read-only makes no durable writes or public comments.
